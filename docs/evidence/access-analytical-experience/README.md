# Who gets access? Candidate delivery

Built from merged main `2bc0062`, after PR54, on `codex/access-analytical-experience`. The existing checkout and its unfinished prototype work were left intact. This candidate changes the published English access exercise and its optional analytical continuation. It is not evidence of improved comprehension, retention or workshop demand.

## Experience and bounded diff

- An original HTML/SVG institutional diagram connects the independent panel or Larch to admission, the secure enclave and publication. The active connection moves when authority changes. Research permissions and the publication route remain constant. Public weights, hosted access and withheld decisions have their own truthful views.
- On narrow screens the diagram precedes the form. A compact progress navigation and “Go to choices” keep the decision reachable. The result displays both submitted reasons and the unchanged authored interpretation; a keyboard-operable control inspects either actual submission without editing it.
- “Read why admission matters” opens an optional reading with a judgment, mechanism, serious tradeoff, changing evidence and a categorical exhibit. The exhibit explicitly leaves unspecified revocation procedures unspecified.
- Existing answer selection, explicit submissions, comparison invalidation, source-tab consultation, reset and exit clearing remain in the shared player. No scored content, payload, locale, storage, API, dependency, telemetry or old evidence file changes.

Files: `episode-player.tsx` integrates the experience; `access-diagram.tsx` renders current/submitted arrangements; `access-presentation.ts` centralizes presentation facts; `access-reading.tsx` supplies the continuation; `access-experience.module.css` scopes styling. The small `exercise.module.css` addition preserves the verification episode's original placement after the shared markup split. Unit and browser tests cover the new state relationships.

## Recommendations for the next PM prompt

1. **Name every journey and important state in a coverage table.** Include Foundation, AI Governance, Security and Technology landings, Standard/Advanced questions, review, results, local/shared Profile, reading, maps and recovery. For each, specify the current gap, acceptance condition, and intentional deferral. A page list alone misses saved drafts, standalone module completion, legacy links, absent answer evidence, ties, withheld choices and localization boundaries. These are precisely where a polished first run can conceal neglected behavior. This is a planning control, not a request for another whole-site screenshot sweep.

2. **Give entry, question and result screens different presentation rules.** The hardware analogy works where there is a concrete relationship to inspect. It is a poor default for every scored question or returning Profile. The module player currently repeats its introduction, Foundation linkage and mode controls above both question/review stages; AI entry repeats route and coverage explanations and still uses explicit Georgia in its mode cards. Prioritize compact, reversible task chrome and the incumbent licensed fonts there. A user should not have to reread a landing page between decisions.

3. **Apply an explanation contract to every result family, without pretending their evidence is interchangeable.** Foundation has local answer evidence; AI leads through axis positions and alternative readings; module results put lane/axis meters before the answers that shaped the result. Require a clear finding, the evidence actually available, a bounded alternative, and a useful continuation for each instrument and mode. Consider moving decisive module answers ahead of the second chart. Preserve scores and issued identities; where a shared payload lacks answer evidence, explain the limit rather than inventing a transcript. This improves the payoff without introducing a universal master score.

4. **Specify the job of Profile after several completions.** It currently lists separate domain records, Perspective Runs and history, and correctly says no reviewed cross-domain relation is available. A longer record collection should still help someone choose what to revisit and what question to examine next. Define behavior for empty, single, multiple-domain, shared and unavailable-history states. Improve navigation and editorial prompts before authorizing synthesis; similar numbers across different scales do not establish a personal trajectory or consistency score.

5. **Track analytical continuations across AI, modules and reference reading.** Current main has four public thinker profiles and all four have reading introductions. Only Keohane and Mearsheimer get an applied-case continuation; Wendt and Strange do not. AI Atlas/Field Guide, module results and thinker pages should each offer a relevant mechanism, substantive counterargument, source scope and onward route. An exercise-to-thinker link should explain why the argument matters, never imply that a decision assigns the reader to that thinker. Equally, preserve a useful stopping point for someone who does not want another questionnaire.

6. **Do not confuse this candidate's reuse potential with an eight-week return loop.** The brief wisely freezes a single journey, but that alone cannot establish repeat value. Define the next publication's editorial promise, what is new for returning readers, how an issue will be found, and the owner's maximum authoring effort. Validate whether readers can explain what changed and why they would return before copying the treatment across the product. That future validation and any collection need their own scope; this task adds none.

7. **Watch framing as closely as factual accuracy.** A prominent enclave diagram may make that arrangement more salient even without a preselected answer. The unchanged invitation also explicitly asks about the developer's veto. Preserve the registered task now; separately test whether the opening wording and visual emphasis direct attention too narrowly. Revocation and findings-export approval remain underspecified fictional terms, not gaps an implementer should silently fill to complete a comparison.
